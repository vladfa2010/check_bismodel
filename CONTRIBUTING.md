# CONTRIBUTING — правила разработки FinModel AI

Для второго разработчика и для себя через полгода. Коротко о том, как здесь
принято работать. Детали по доменам — в docs/ (индекс в README).

## 1. Устройство репозитория

```
backend/      FastAPI: main, routes_{auth,chat,files}, db, kimi, docparse, cleanup, security, config
static/       весь фронт — один index.html (см. docs/frontend.md, почему так)
deploy/       docker-compose, Caddyfile, bootstrap (prod — Beget VDS)
tests/        e2e на Playwright (см. docs/tests.md)
docs/         вся документация; новый аспект системы = новый файл сюда
```

## 2. Обязательный цикл любой правки

1. Код.
2. **E2E зелёный локально** (`docs/tests.md`, прогон с чистым DATA_DIR).
   Правка без прогона не коммитится.
3. Документация обновлена, если правка меняет поведение/контракт.
   «Код без документации» считается незаконченным.
4. Коммит атомарный: одна правка = один коммит, сообщение по-русски,
   сути (`docs:`, `fix:`, `feat:` — по смыслу, не догма).
5. Пуш в main (трюков с ветками пока нет — два юзера, один прод).

## 3. Жёсткие правила (нарушение = ревью-стоп)

- **Секретов в репо нет.** Только имена env-переменных. Тестовые пароли —
  через `E2E_PASSWORD`. Перед коммитом: `git diff --cached | grep -iE
  'sk-|pat_|password'` глазами.
- **rsync на прод — только whitelist-путей** (docs/deploy.md). `.env` живёт
  только на сервере.
- **Миграции БД — только additive** (docs/data-model.md, раздел 4).
- **Изоляция по `user_id` в каждом запросе** к данным; чужое = 404, не 403.
- **Пользовательский ввод в DOM — через escapeHtml/textContent.**
- **LLM вызывается только через KimiGateway** — никаких прямых httpx-запросов
  к провайдерам из роутов.

## 4. Как принимаются решения

- Продуктовые — через roadmap (docs/roadmap.md): фича сначала получает
  срез/критерии, потом код. Запрос один раз произнесённый — не фича.
- Инженерные quirks (неочевидное поведение API, бага, обход) — фиксируются
  в соответствующем docs/*.md в том же коммите, что и код. Не зафиксировано =
  будет наступлено повторно.
- «Честно о неработающем» важнее «красиво в отчёте»: известные ограничения
  перечисляются в docs/security.md и roadmap, а не замалчиваются.

## 5. Тесты

- Любая новая фича получает e2e-сценарий в том же срезе (правила написания —
  docs/tests.md: детерминизм, сигналы вместо sleep, одна проверка = один факт).
- Тесты не ходят ни в какие платные API: mock-режим (`MOCK_KIMI=1`).
- Прогон против прода — только осознанно (`BASE=https://…`).

## 6. Деплой

Ручной: rsync + `docker compose up -d --build` (docs/deploy.md, раздел 4).
Автодеплой из GitHub Actions — написан, ждёт PAT со scope `workflow`.
Долгие сборки — через nohup (docs/runbook.md, почему).
