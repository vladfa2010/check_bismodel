# Тестирование FinModel AI

Единый файл: правила + реестр проверок + эксплуатация. Когда появятся unit/API-слои
или реестр перевалит за ~50 проверок — пилится на `testing-rules.md` и `testing-cases.md`.

---

## 1. Правила

**Что тестируем.** Только сквозные пользовательские сценарии (e2e) в настоящем браузере.
Не curl-имитация, не моки DOM: реальный Chromium, реальный сервер, реальная SQLite.
Логика: если e2e зелёный — продуктом можно пользоваться.

**Технологии.**

| Слой | Инструмент | Зачем |
|---|---|---|
| Браузер | Playwright (sync API) + системный Chromium `/usr/bin/chromium`, headless, `--no-sandbox` | клики, формы, SSE-стрим, reload — как у юзера |
| Сервер | uvicorn + FastAPI, поднятый локально на порту 8123 | тот же код, что в проде |
| LLM | `MOCK_KIMI=1` — детерминированная заглушка шлюза | e2e не жжёт токены и не зависит от сети/лимитов API |
| Данные | чистый `DATA_DIR=/tmp/fme2e` на каждый прогон, SQLite в WAL | изоляция прогонов, ноль состояния |
| API-проверки | `page.request` (Playwright APIRequestContext) внутри тех же сценариев | 401 без сессии, изоляция файлов, брутфорс — без браузерной обвязки |

**Жёсткие правила написания проверок.**

1. **Детерминизм.** Никаких «подождал 2 секунды — надеюсь, успело». Ждём сигналы:
   `wait_for_selector`, `wait_for_function` по состоянию DOM. Единственное исключение —
   `time.sleep(1.5)` после reload на догрузку `/api/usage` (обосновано в коде).
2. **Чистое окружение.** Перед прогоном `rm -rf $DATA_DIR` и перезапуск сервера.
   Грязная БД валит проверки счётчиков («ровно 1 файл» и т.п.) — это не баг приложения.
3. **Сценарии идут в одном браузерном контексте и опираются друг на друга** (сессия victor
   из сценария 5 используется в 7–9; сценарий 10 — отдельный мобильный контекст). Новый сценарий обязан явно документировать,
   в каком состоянии ожидает страницу.
4. **Одна проверка = один факт.** Формат `check(имя, условие, деталь)`; в деталь — фактические
   значения, чтобы по падению было видно «ожидали/получили» без перезапуска.
5. **Реальные пароли только тестовые — и те через env.** Боевые секреты в тестах не храним;
   даже тестовый пароль юзеров передаётся через `E2E_PASSWORD`, а не лежит в коде
   (раньше лежал захардкоженным — вынесен после аудита). Сервер поднимается
   с `SESSION_SECRET=testsecret` и своим `SEED_USERS`.
6. Тест **не ходит в прод** по умолчанию. Прогон против прода — только осознанно,
   `BASE=https://…`, с пониманием, что он создаёт данные (файл в аккаунте vlad).

## 3. Прогон

```bash
# 1. тестовый сервер (mock LLM, чистые данные, свои тестовые юзеры)
cd app
rm -rf /tmp/fme2e
MOCK_KIMI=1 DATA_DIR=/tmp/fme2e SESSION_SECRET=testsecret \
  SEED_USERS='{"vlad":"e2e-pass","victor":"e2e-pass"}' \
  python3 -m uvicorn backend.main:app --host 127.0.0.1 --port 8123 &

# 2. тесты (пароль НЕ из репо — через env)
E2E_PASSWORD='e2e-pass' python3 tests/e2e_test.py   # exit 0 = всё зелёное
```

Требования окружения: `playwright` (pip) + системный Chromium. Переменные:
`BASE` (default `http://127.0.0.1:8123`), `CHROMIUM` (default `/usr/bin/chromium`),
`E2E_PASSWORD` (обязательная — пароль seed-юзеров тестового сервера; без неё тесты
падают сразу, `KeyError`). Тестовый сервер сидится своим `SEED_USERS` — пароль в
тестах и в `SEED_USERS` должен совпадать, но это тестовый секрет, не боевой.

## 4. Известные грабли (по шрамам)

1. **Гонка «стрим vs перезагрузка»**: `reload` сразу после появления текста ответа рвёт SSE до
   записи usage в БД. Лечение: ждать автообновления счётчика (`запросов: N`) как сигнала
   завершения — так и написано в сценарии 4.
2. **Грязный DATA_DIR**: повторный прогон без `rm -rf` валит проверки «ровно 1 файл».
3. **Убийство сервера по имени**: `pkill/pgrep -f "uvicorn backend.main"` совпадает с командной
   строкой самой оболочки → самоубийство шелла. Только `fuser -k 8123/tcp`.
4. **Кеш браузера у реальных юзеров**: после деплоя старый HTML с старым JS. На проде Caddy
   отдаёт `Cache-Control: no-cache` для HTML; в тестах headless-браузер стартует без кеша.
5. **Смена разметки ломает селекторы**: после добавления меню «⋯» в строке диалога стало
   5 кнопок вместо 1 — селектор `#historyList button` превратился в минное поле.
   Правило: адресуемся по осмысленным классам (`.chat-open`), не по тегам.
