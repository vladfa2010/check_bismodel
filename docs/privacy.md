# Данные пользователей: что храним и куда отдаём

Внутреннее описание data flows — основа для будущей публичной
privacy-страницы (срез №5). Пишем как есть, включая неудобное. Пока
пользователей двое и оба — команда, документ честный, а не юридический.

## 1. Что храним

| Данные | Где | Зачем | Срок |
|---|---|---|---|
| Логин | БД `users` | вход | пока жив аккаунт |
| Хеш пароля | БД `users` | вход (PBKDF2, сам пароль не хранится) | пока жив аккаунт |
| Содержимое диалогов | БД `messages` | контекст для LLM, история | до удаления диалога |
| Загруженные файлы | диск `DATA_DIR/files/<uid>/` | извлечение параметров модели | до удаления + 7 дней корзины |
| Извлечённый текст файлов | диск рядом с файлом | контекст для LLM | вместе с файлом |
| Счётчики токенов | БД `usage_events` | контроль расходов, будущие квоты | бессрочно (агрегаты без контента) |
| `last_seen_at` | БД `users` | retention анонимов | пока жив аккаунт |

**Не храним:** пароли в открытом виде, содержимое ответов LLM в логах,
IP-адреса (кроме эфемерных счётчиков анти-брутфорса в памяти), cookies кроме
одной сессионной `fm_uid`.

## 2. Куда данные уходят (третьи стороны)

| Получатель | Что уходит | Когда |
|---|---|---|
| Moonshot AI (api.moonshot.ai) | текст диалога + извлечённый текст документов | каждый ответ Kimi K3 |
| MiniMax (api.minimax.io) | то же | каждый ответ MiniMax M3 |
| Moonshot Files API | **сам файл целиком** | только fallback: PDF-скан без текстового слоя |

Принципы:
- **Провайдеру уходит текст, не файл.** Основной парсинг — локальный
  (docparse); файлы покидают сервер только в исключительном случае скана.
- В контекст попадает история текущего диалога и документы юзера — то есть
  содержимое диалога **всегда** доступно LLM-провайдеру. Это неизбежно для
  чат-продукта и должно быть сказано юзеру прямо, когда появятся внешние.
- Оба провайдера — иностранные юрлица; данные покидают РФ. Для b2c-выхода
  это пункт публичной политики и, возможно, выбор провайдера.

## 3. Кто имеет доступ внутри

- Юзер видит только своё (изоляция по `user_id`, 404 на чужое — docs/security.md).
- У root на VDS — доступ ко всему: БД, файлы, `.env`. Это владелец продукта.
- У агента-разработчика (ИИ) в сессиях разработки был SSH-доступ и секреты
  — см. ограничение 5 в security.md (ротация).

## 4. Удаление

| Действие юзера | Что происходит |
|---|---|
| Удалить диалог | сообщения стираются сразу; файлы диалога — в корзину (7 дней) |
| Удалить файл | корзина 7 дней → физическое стирание файла и его текста |
| (будущее) Удалить аккаунт | `delete_user_cascade`: всё, включая файлы и usage |

- Резервных копий нет → удалённое действительно удалено (обратная сторона:
  восстановить нельзя).
- У LLM-провайдеров мы не контролируем retention того, что ушло в API;
  пресет: считаем отправленное скомпрометированным для целей «полного
  удаления». Для внешних юзеров это будет явный пункт политики.

## 5. Что обязательно до внешних пользователей (срез №5)

1. Публичная privacy-страница простым языком (из этого документа).
2. Бэкапы (иначе «удаление навсегда» превращается в «потеря навсегда»).
3. Явное согласие на передачу данных LLM-провайдерам при регистрации.
4. Кнопка «удалить аккаунт» (механика каскада уже есть).
5. Аудит-лог (кто/когда — сейчас не пишется).
